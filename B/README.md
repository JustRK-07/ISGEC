# Approach B — 2-block overlay

Each drawing is wrapped in its own block:

- `MECH_DRAWING` block — MECH entities at original MECH coords
- `STR_DRAWING` block — STR entities at original STR coords

Modelspace has exactly **2 INSERTs**. The gridline-derived affine lives in
the `STR_DRAWING` INSERT's `(insert, xscale, yscale)` — no per-entity
transform needed.

## Color policy

**Forced 2-color** for at-a-glance readability:

- **Every MECH layer** (non-prefixed) is set to ACI color **1 (red)**
- **Every STR layer** is renamed with `_BLUE_` prefix and set to ACI
  color **5 (blue)**
- Per-entity color overrides on STR entities are reset to ByLayer (256)
  so they inherit the layer blue

This is the standard convention for engineering overlay drawings: red for
mechanical, blue for structural.

> See `A/README.md` if you want entities to keep their source colors
> instead. See `C/README.md` for the 1-block equivalent.

## Structure

```
Modelspace:
  INSERT MECH_DRAWING  pos=(0, 0)             xscale=1
  INSERT STR_DRAWING   pos=(208379.86, -179584.52)  xscale=1.0  yscale=1.0
     │
     └─ STR_DRAWING block contains:
         ├─ 1,953 INSERTs to GridLine-*, Part-*, Bolt-*, Connection-*
         └─ _BLUE_* layers (color 5 = blue)
```


## Output

- **File**: `out/TP-104 OVERLAY_B.dxf` (~18 MB)
- **Modelspace**: **2 INSERTs** only
  - `MECH_DRAWING` at origin
  - `STR_DRAWING` at the affine-derived position with embedded scale
- **Editability**: MEDIUM — click `STR_DRAWING` to grab the whole STR
  layer; double-click into the block to edit individual entities

## Why pick B over A

- You want **forced red/blue** for high-contrast overlay
- You want to **toggle STR on/off** with one click (delete the
  `STR_DRAWING` INSERT)
- You might re-align the overlay **later** by moving the
  `STR_DRAWING` INSERT position without re-running the script
- You want to keep MECH and STR as separate logical units

## Why pick B over C

- You want to *individually* edit STR members (B lets you
  double-click into `STR_DRAWING`; in C you'd double-click into the
  monolithic `OVERLAY_DRAWING`)
- You want the MECH and STR blocks to be **independently movable**
  (B exposes both as top-level INSERTs; C merges them into one block)

See `../A/` and `../C/` for the per-entity and 1-block alternatives.
