03 / PROBLEM

Manual cross-discipline reviews miss the things that cost the most.

Mechanical, structural, and superimposed drawings all describe the same physical space — but they're authored by different teams using different conventions. Errors slip through. Always have.

PROBLEM 01

Missed Supports

Mechanical GA requires a support at TP104-B/2; Structural GA doesn't show it.

→ Equipment sags. Vibration. Premature failure.
PROBLEM 02

Wrong-Sized Openings

Required 300×200 duct opening. Provided 250×200.

→ Field rework. Cost overruns. Schedule slip.
PROBLEM 03

Undetected Clashes

A required opening falls directly on a primary beam.

→ Demo. Rebar redesign. RFI cascade.
PROBLEM 04

Tolerance Drift

Position off by 60 mm when only ±25 mm is permitted.

→ Misalignment cascades through the system.

[ Today these checks are manual, slow, inconsistent across reviewers, and easy to skip under deadline pressure. ]

05 / CAPABILITIES

Five capabilities built for engineering defensibility.

Not abstract AI. Specific, auditable capabilities that map to the things your reviewers actually check.

01 SCHEMA

One canonical schema for every firm's drawing convention.

The Normalization Agent reads each drawing in its native style — Bechtel tags, Fluor section codes, EPC vendor conventions — and emits a single canonical JSON schema. Downstream rules never have to learn firm-specific formats.

  • Support taxonomy: restraint | anchor | guide | saddle
  • Opening taxonomy: duct | pipe | cable-tray | sleeve | trench
  • Member taxonomy: beam | column | brace | truss | joist
  • Auto-detection of tag patterns: F11WE, TP4BM101, M-OP-203
  • Sheet metadata: rev, drawn-by, scale, units

03 MATCHING

Fuzzy ID matching that handles inconsistent tagging.

Mech and Str drawings rarely share the same tag for the same physical item. The matching engine combines Levenshtein distance, semantic embeddings, and grid proximity to pair items correctly.

  • Levenshtein-based fuzzy string match
  • Sentence-transformer semantic similarity
  • Grid-bubble proximity weighting
  • Confidence-banded output (Pass / Verify / Manual)
  • Reviewer override on every match

04 CLASH

Polygon-level clash with real clearance values.

Bounding boxes are too coarse. The clash engine converts every footprint and member into polygons (or extruded shapes for 3D), then computes true geometric intersection and clearance distance using Shapely.

  • Polygon intersection — not bounding boxes
  • Clearance zone violations (mm)
  • Hard clash vs soft intrusion classification
  • Multi-discipline overlays (Mech + Str + Arch + Plumbing)
  • 3D-ready (trimesh + IFC support)
  • Beam-vs-opening conflict as first-class check

06 / HOW IT WORKS

From upload to signed report in 5–15 minutes.

01STEP

Upload Drawings

Drop in Mechanical GA, Structural GA, and (optional) Superimposed as native DWG files. DXF, IFC, and RVT also supported.

02STEP

Detect & Register

The Ingestion Agent hashes files, detects vector vs raster, and registers each sheet to a unified coordinate frame using grid bubbles.

03STEP

Match & Check

The Normalization Agent builds canonical element lists. The Rule Engine runs 8 deterministic checks. Findings stream into the inspector panel.

04STEP

Sign Off

Click any finding to jump to its location. Approve, override, or comment. Export a signed PDF report with full audit trail.

▶ PRIMARY PATH · DWG-NATIVE

Layers, blocks, and real-world units.

DWG files are converted to DXF (text format) via the free ODA File Converter, then parsed by ezdxf in pure Python. We read every entity — lines, polylines, text, hatches, blocks, dimensions — with its layer, color, and line type intact. Coordinates are already in millimeters.

▶ SECONDARY PATH · LEGACY SCANS

AI reads what humans read.

For paper-only legacy archives, scanned sheets go through a local multimodal LLM with Tesseract OCR fallback. The agent reads tags, dimensions, and symbols — and produces the same canonical JSON schema as the DWG path. All inference runs on-prem.
