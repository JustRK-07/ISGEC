## Original prototype description

Every STR entity is copied into MECH's modelspace and **baked** at its
final (transformed) coordinates. STR geometry is not wrapped in a block —
it's loose in modelspace alongside MECH.

## Files in this prototype

| File | Purpose |
|---|---|
| `fit_transform.py` | Reads both clean3 DXFs, finds labeled gridlines (TP104-A/B/C/D + 1/2/3), fits a 2-axis affine transform by least squares, writes `transform.json` |
| `overlay.py` | Reads `transform.json`, imports + transforms STR entities in place, saves `TP-104 OVERLAY_A.dxf` |
| `transform.json` | Generated by `fit_transform.py`. Contains `scale_x`, `scale_y`, `tx`, `ty`, the matched label pairs, and per-intersection residuals |
| `TP-104 OVERLAY_A.dxf` | Generated. MECH (red) + STR (blue) overlaid |

## Original usage (legacy)

```bash
cd A_per_entity
python3 fit_transform.py     # step 1 — derive transform from gridlines
python3 overlay.py           # step 2 — build overlay
```

## Migrate to the canonical implementation

```bash
cd ../../A/        # ISGEC/A/
./run.sh           # produces out/TP-104 OVERLAY_A.dxf
```

The canonical script (`../../A/scripts/overlay.py`) is functionally
identical but:
- Uses `Path(__file__).resolve().parent` self-locating paths
- Falls back to existing `dxf/*_clean3.dxf` when ODA File Converter is
  unavailable
- **Preserves original layer/entity colors** (this prototype forced red
  MECH / blue STR)
