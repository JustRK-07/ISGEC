# Approach A — Per-entity overlay

Every STR entity is copied into MECH's modelspace and **baked** at its
final (transformed) coordinates. STR geometry is not wrapped in a block —
it's loose in modelspace alongside MECH.

## Color policy

**Approach A preserves ORIGINAL colors.** When STR blocks/entities are
imported:

1. Layers are renamed `LayerX` → `_STR_LayerX` to avoid MECH/STR name
   collisions.
2. The new `_STR_LayerX` layer is created with the **source layer's
   color** (looked up from `str_doc.layers`).
3. Per-entity color overrides on STR entities are **kept** (not reset
   to ByLayer).
4. MECH layers are untouched (every one of the 17 original layer colors
   is preserved).

So a steel beam stays gray, a magenta hatch keeps its source color, an
orange pipe stays orange. Use this approach when you want the overlay to
look faithful to the source drawings.

> See `B/README.md` or `C/README.md` if you want the traditional
> red-MECH / blue-STR forced color scheme.

## Editability

**HIGHEST** of the three. Click any structural member in your CAD
viewer to edit it directly — there's no block wrapper to navigate
through.

## What this directory contains

```
A/
├── README.md           (this file)
├── run.sh              one-shot driver (clean → fit → overlay)
├── scripts/
│   ├── clean.py        Step 1: DWG→DXF + strip annotations/markers/triangles
│   ├── fit.py          Step 2: find labeled gridlines, solve affine, write transform.json
│   └── overlay.py      Step 3: per-entity overlay (this approach; preserves colors)
├── input/              source DWGs (symlinks to ../dwg/)
├── work/               intermediate cleaned DXFs (generated)
├── transform.json      affine transform (generated by fit.py)
└── out/
    └── TP-104 OVERLAY_A.dxf     ← final overlay (~18 MB)
```

## How to run

```bash
cd A/
./run.sh
ls -la out/
```

Or run the steps individually for debugging:

```bash
python3 scripts/clean.py     # → writes work/TP-104 *_clean3.dxf
python3 scripts/fit.py       # → writes transform.json
python3 scripts/overlay.py   # → writes out/TP-104 OVERLAY_A.dxf
```

Or use the multi-approach driver from the ISGEC root:

```bash
cd ../    # back to ISGEC/
python3 run_to_dxf.py        # overlay-only, fast
python3 run_to_dxf.py --rewrite-clean   # full clean + fit + overlay
```

## Output

- **File**: `out/TP-104 OVERLAY_A.dxf` (~18 MB)
- **Modelspace**: 2,242 entities (2025 INSERTs + 217 others)
  - 1,953 STR INSERTs (snapped to `(0, 0, 0)` with `xscale = 1`)
  - 1953 STR top-level entities, pre-scaled + affine-transformed
  - 289 MECH entities (untouched)
- **Layer colors preserved** (MECH: 17 unique colors; STR: source colors)

## When to pick Approach A

- ✅ You need to edit individual structural members after overlay
- ✅ You want a faithful overlay that doesn't rebrand colors
- ✅ You want a clean modelspace (no wrapper INSERT)

See `../B/` and `../C/` for the 2-block and 1-block alternatives.
