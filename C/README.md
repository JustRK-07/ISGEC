# Approach C — 1-block overlay

Both MECH and STR are merged into a single `OVERLAY_DRAWING` block:

- All MECH entities (red, at original coords)
- All STR entities (blue, transformed to MECH coords)

Modelspace has exactly **one INSERT** at the origin.

## Color policy

**Forced 2-color** (same convention as Approach B):

- **Every MECH layer** is set to ACI color **1 (red)**
- **Every STR layer** is renamed with `_STR_` prefix and set to ACI
  color **5 (blue)**
- Per-entity color overrides on STR entities are reset to ByLayer (256)
  so they inherit the layer blue

> See `A/README.md` if you want entities to keep their source colors
> instead. See `B/README.md` for the 2-block equivalent of the same
> color policy.

## Structure

```
Modelspace:
  INSERT OVERLAY_DRAWING pos=(0, 0)  xscale=1
     │
     └─ OVERLAY_DRAWING block contains:
         ├─ 289 MECH entities (red, layer colors set to ACI 1)
         ├─ 1,953 INSERTs to GridLine-*, Part-*, Bolt-*, Connection-*
         ├─ 16,015 inner entities inside _STR_* blocks (blue)
         └─ _STR_* layers (color 5 = blue)
```

## How to run

```bash
cd C/
./run.sh
ls -la out/
```

Or via the multi-approach driver:

```bash
cd ../    # back to ISGEC/
python3 run_to_dxf.py
```

## Output

- **File**: `out/TP-104 OVERLAY_C.dxf` (~18 MB)
- **Modelspace**: **1 INSERT** only — `OVERLAY_DRAWING` at origin
- **Editability**: LOW — single grab, the whole overlay moves as one

## Why pick C over A or B

- You want a **single atomic** overlay object (move/scale/delete with
  one click)
- You don't need per-layer or per-entity toggling
- You're embedding the overlay into another assembly drawing as one unit

## Why NOT C

- To edit individual entities you must `double-click` into the massive
  `OVERLAY_DRAWING` block — slow with 16,015 entities inside
- No way to toggle just STR off without deleting the whole block
- No way to re-align later without re-running the pipeline (the
  `STR_DRAWING` exposure of B is lost)

See `../A/` and `../B/` for the per-entity and 2-block alternatives.
